# Security Policy

## Supported Versions

Security fixes are applied to the latest commit on `main` and to the current production deployment. Older commits, forks, and locally modified copies are not maintained as supported releases.

## Reporting a vulnerability

Report suspected vulnerabilities privately through GitHub's **Security** tab by selecting **Report a vulnerability**.

Do not open a public issue, discussion, or pull request that contains exploit details, credentials, tokens, personal data, or steps that could put the production service at risk.

A useful report includes:

- The affected route, component, dependency, or commit
- The security impact and realistic attack scenario
- Reproduction steps or a minimal proof of concept
- Expected and observed behavior
- Any known mitigations or remediation ideas

We aim to acknowledge a complete report within three business days. Status updates will be provided through the private advisory while the issue is validated and remediated.

## Disclosure

Please allow reasonable time for validation, remediation, deployment, and user protection before publishing technical details. Coordinated disclosure timelines may vary with severity and operational risk.
